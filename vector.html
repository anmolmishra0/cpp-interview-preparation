C++ std::vector — Principal-Level Interview Notes

1. Vector Mental Model

std::vector<T> is a contiguous dynamic array.

vector
 ┌───────────────┐
 │ data pointer  │ ──────► [ T ][ T ][ T ][ T ][ ... ]
 ├───────────────┤
 │ size          │
 ├───────────────┤
 │ capacity      │
 └───────────────┘
  • size() — number of constructed elements
  • capacity() — number of elements that can be stored before reallocation
  • data() — pointer to contiguous element storage

2. Vector Constructors — C++11/C++14

Empty vector

std::vector<int> v;

Size constructor

std::vector<int> v(5);

Creates 5 value-initialized integers: 0 0 0 0 0.

Size + value

std::vector<int> v(5, 10);

Creates: 10 10 10 10 10.

Initializer-list constructor — C++11

std::vector<int> v{1, 2, 3, 4, 5};

Important difference:

std::vector<int> a(5, 10);   // 10 10 10 10 10
std::vector<int> b{5, 10};   // 5 10

Iterator-range constructor

int arr[] = {1, 2, 3, 4};
std::vector<int> v(arr, arr + 4);

Copy constructor

std::vector<int> a{1,2,3};
std::vector<int> b(a);

Move constructor — C++11

std::vector<int> a{1,2,3};
std::vector<int> b(std::move(a));

Typically, the destination takes ownership of the source vector's allocated buffer. The moved-from vector remains valid but has an unspecified state.

4. reserve() vs resize()

std::vector<int> v;

v.reserve(100);
// size == 0
// capacity >= 100

v.resize(100);
// size == 100
Remember: reserve() prepares memory; resize() changes the number of elements.

5. push_back() vs emplace_back()

std::vector<std::string> v;

v.push_back("hello");
v.emplace_back("hello");

emplace_back() constructs the object in the vector using constructor arguments. Do not claim that it is always faster; the benefit depends on the type and expression.

6. What Happens When push_back() Causes Reallocation?

If capacity is exhausted, vector generally:

  1. Allocates a larger memory block.
  2. Moves or copies existing elements.
  3. Constructs the new element.
  4. Destroys old elements when required.
  5. Releases the old storage.
  6. Updates its internal state.

Therefore an individual push_back() can be O(n), while repeated push_back() is amortized O(1).

7. Why Is push_back() Amortized O(1)?

Vector implementations generally grow geometrically. The standard does not require a particular growth factor.

1 + 2 + 4 + 8 + ... + n = O(n)

n insertions = O(n) total work
Average per insertion = O(1)

8. Cache Locality

Vector stores elements contiguously:

[10][20][30][40][50]

When the CPU fetches a cache line containing one element, nearby elements are likely to be fetched too. Sequential traversal can therefore make efficient use of CPU caches.

A list typically stores elements in separately allocated nodes that may be scattered in memory, resulting in pointer chasing and potentially more cache misses.

Principal-level point: Big-O is not the whole performance story. Cache locality, allocation overhead, pointer chasing, memory footprint, and branch behavior can strongly affect real-world performance.

9. Pointer / Iterator Invalidation

Consider:

std::vector<int> v{1,2,3};

auto p = &v[0];

v.push_back(4);

std::cout << *p;

Case 1: Reallocation occurs

Old memory:
[1][2][3]   <-- p

New memory:
[1][2][3][4]

The old storage is released. p becomes a dangling pointer. Dereferencing it is undefined behavior.

Case 2: No reallocation

size     = 3
capacity = 5

The fourth element can use existing storage:

[1][2][3][4][ ]
 ↑
 p

Here p remains valid and dereferencing it gives 1.

Interview answer: Do not simply say the program prints 1. The correct answer is that the result depends on whether push_back() reallocates. If reallocation occurs, dereferencing p is undefined behavior.

10. Making the Above Example Safe

std::vector<int> v{1,2,3};

v.reserve(4);

auto p = &v[0];

v.push_back(4);

std::cout << *p;   // safe for this push_back

reserve(4) prevents reallocation for this particular insertion. However, insertions and erasures have their own invalidation rules.

11. erase() and the Erase-Remove Idiom

v.erase(
    std::remove_if(v.begin(), v.end(),
                   [](int x) {
                       return x < 0;
                   }),
    v.end()
);

remove_if() rearranges the elements and returns a new logical end; erase() removes the unwanted tail.

12. clear()

std::vector<int> v{1,2,3,4,5};

v.clear();

After clear(), size becomes zero. Capacity is not required to decrease.

13. shrink_to_fit()

v.shrink_to_fit();

This is a non-binding request. The implementation is allowed not to reduce capacity.

14. operator[] vs at()

v[10];       // no bounds checking

v.at(10);    // bounds checking; throws std::out_of_range if invalid

15. vector<bool>

std::vector<bool> is a special library specialization designed to pack boolean values efficiently, so it does not behave exactly like an ordinary vector<T>.

16. Why vector Often Beats list

Even though a list can provide O(1) insertion when an iterator to the insertion point is already available, vector often performs better for practical workloads because of:

  • contiguous memory
  • better cache locality
  • fewer pointer indirections
  • lower allocation overhead
  • better sequential traversal

17. noexcept, Move and Vector Reallocation

During vector reallocation, existing elements may need to be moved or copied. A noexcept move constructor is valuable because it allows vector to safely prefer moving in situations where exception guarantees matter.

class Data {
public:
    Data(Data&&) noexcept;
};

18. Important C++11 Features

  • initializer-list construction
  • move construction and move assignment
  • emplace()
  • emplace_back()
  • cbegin()/cend()
  • crbegin()/crend()
  • data()
  • range-based for loops

19. C++14

C++14 did not introduce a major new group of vector APIs comparable to the C++11 additions. For C++14 interviews, focus on understanding the C++11 vector features and the language/library improvements around them.

  5. When does erase() invalidate iterators?
  6. Why can vector outperform list despite list's O(1) insertion?
